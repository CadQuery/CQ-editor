# Installation

The release installers are self-contained. They include the native CQ-editor,
Python 3.12.15, CadQuery 2.8, OCP 7.9 and Jedi, so a new user does not need to
install Python, conda or CadQuery first.

## Download an installer

Open the [CQ-editor releases](https://github.com/igors93/CQ-editor/releases)
page and choose the file for your computer:

| System | Installer |
| --- | --- |
| Windows 10/11, 64-bit | `Windows-x86_64.exe` |
| macOS on Apple Silicon (M1 or newer) | `MacOSX-arm64.pkg` |
| macOS on Intel | `MacOSX-x86_64.pkg` |
| Linux, 64-bit x86 | `Linux-x86_64.sh` |

The release also contains `SHA256SUMS.txt`. Verify the download before running
it when possible:

```sh
# Linux or macOS, from the download folder
sha256sum -c SHA256SUMS.txt --ignore-missing
```

On Windows, compare this command's result with the matching line in
`SHA256SUMS.txt`:

```powershell
Get-FileHash .\CQ-editor-*.exe -Algorithm SHA256
```

### Windows

Run the `.exe`, choose **Just Me** for a normal per-user installation, and
finish the wizard. CQ-editor appears in the Start menu and in **Open with** for
Python files. It does not replace the system Python or add its private runtime
to `PATH`.

### macOS

Run the `.pkg` matching the Mac's processor. The runtime is installed under
the user's Library and **CQ-editor.app** is added to Applications. Intel and
Apple Silicon packages are built and tested separately rather than relying on
emulation.

### Linux

Make the downloaded installer executable and start its interactive wizard:

```sh
chmod +x CQ-editor-*-Linux-x86_64.sh
./CQ-editor-*-Linux-x86_64.sh
```

The default is `~/.local/share/CQ-editor`. The installer creates an application
menu entry and registers CQ-editor as an option for opening Python files. A
typical desktop Linux installation already has the GTK/X11 or Wayland system
libraries used by the native window.

Published Windows installers are Authenticode signed and timestamped. The
macOS packages are Developer ID signed, notarized by Apple and stapled.
Release CI refuses to upload or publish those artifacts if signing or
notarization fails. Windows SmartScreen can still warn until a new signing
certificate has built up reputation.

## What is verified before publication

Release CI builds four native artifacts: Linux x86_64, Windows x86_64, macOS
Apple Silicon and macOS Intel. On the matching operating system it then:

1. runs the finished installer in unattended mode;
2. imports CadQuery, OCP and Jedi with the installed Python;
3. verifies the expected CadQuery version; and
4. starts the installed CQ-editor executable with `--help`.

Only when all four jobs pass, including signature and notarization checks, are
the installers and their checksums attached to the GitHub release. Each build
also records a dependency lockfile and the
third-party license inventory generated by constructor.

## First start

Launch CQ-editor from the application menu. The status bar briefly shows
**Starting Python…** while the bundled CadQuery runtime is imported, then
shows the versions in use, for example **Python 3.12 · CadQuery 2.8.0**. Hover
the status to see the OCP version, and press **F5** to render.

![First launch](../images/first-launch.png)

The installer keeps the runtime private so it cannot change another Python
installation. Advanced users can still install extra Python packages with the
bundled `pip`, or select a completely different compatible environment in
**Edit > Preferences > General > Python interpreter**.

## Use another Python environment

This section is optional for installed releases and useful for add-ons,
development or source builds.

| | Supported |
| --- | --- |
| Python | 3.11–3.14 with a matching supported CadQuery version |
| Recommended external environment | Python 3.11–3.14 with CadQuery 2.8 |
| Previous CadQuery release | Python 3.11 with CadQuery 2.7 |

The exact tested combinations are in the
[CadQuery/OCP compatibility matrix](../development/dependency-compatibility.md).

**From CQ-editor.** *Preferences > General > Python interpreter* manages
environments without a terminal:

* **Detected** lists the Pythons found on this computer (the active and
  conda/mamba environments, `.venv` folders, python.org installs and `PATH`);
  pick one, then **Restart Python with this interpreter**.
* **Create Environment…** makes a virtual environment (`python -m venv`) in a
  folder of your choice, by default `environments/cadquery` in the folder
  below, with a supported Python (3.11 or newer, the one in use by
  default), and installs CadQuery and jedi into it. Add other packages to the
  list as for `pip install`. Downloading CadQuery takes a few minutes; the
  window shows pip's output and can cancel it. **Use this environment**
  switches to it and restarts Python.
* **Install Packages…** runs `pip install` for the packages you name in the
  Python in use (or another one), for example `trimesh numpy-stl`; then
  restart Python to import them.

Package names are passed to pip as they are, with versions or extras
(`ocp-vscode>=2`, `trimesh[easy]`) or a local `.whl` file, but pip options
are refused. No command goes through a shell.

**pip and a virtual environment**

```sh
python -m venv .venv
# Windows:      .venv\Scripts\pip install cadquery jedi
# Linux/macOS:  .venv/bin/pip install cadquery jedi
```

**conda / mamba**

```sh
mamba create -n cadquery -c conda-forge cadquery=2.8 jedi
mamba activate cadquery
```

Start CQ-editor with a one-session override:

```sh
cq-editor --python /path/to/environment/bin/python my_part.py
```

| Option | Meaning |
| --- | --- |
| `FILE` | CadQuery script to open |
| `--python PATH` | Python interpreter to use for this session |
| `-h`, `--help` | Print the usage text |

## How CQ-editor finds Python

The first match wins (`src/worker/launch.rs`):

1. `--python PATH`, or the interpreter selected in Preferences;
2. the `CQ_EDITOR_PYTHON` environment variable;
3. the runtime bundled beside an installed CQ-editor executable;
4. an active virtual or conda environment (`VIRTUAL_ENV` or `CONDA_PREFIX`);
5. a `.venv` beside the executable or in the working directory (debug builds
   also look in the source tree);
6. `python` on Windows or `python3` on Linux and macOS from `PATH`.

The two explicit choices remain ahead of the bundled runtime, so installing a
self-contained release does not remove control from users who need a custom
CadQuery environment.

## Build from source

Source builds need Rust 1.88 or newer and a compatible Python/CadQuery
environment:

```sh
git clone https://github.com/igors93/CQ-editor.git
cd CQ-editor
cargo build --release
```

The executable is written to `target/release/cq-editor` (`cq-editor.exe` on
Windows). Linux needs a few system packages first, and Windows has two
toolchain options. [Building](../development/building.md) covers both.

## Where CQ-editor keeps its files

Settings and recovery data live in one per-user folder:

| System | Folder |
| --- | --- |
| Windows | `%APPDATA%\cq-editor\data\` |
| Linux | `~/.local/share/cq-editor/` |
| macOS | `~/Library/Application Support/cq-editor/` |

| Entry | Content |
| --- | --- |
| `app.ron` | Preferences, recent files, panel layout and window position |
| `recovery/` | Crash-recovery session and local history |
| `logs/` | Current and previous application logs |
| `worker-<hash>/` | Extracted embedded worker; obsolete versions are removed automatically |
| `environments/` | Default place of the environments created from the preferences |

Deleting `app.ron` while the editor is closed restores all defaults.
